# 作業說明：建立自己的 AGENTS.md

## 我的專案

我選擇以「魔法師的學徒」塔羅學習 App 作為基礎，製作一份獨立的學習網站作業。使用者可以查閱牌面、進行抽牌練習，再透過學習單元練習觀察與記錄。

這次沒有修改原本的 App，而是另外建立作業副本。重點是把做法整理成可延續的規則，讓之後新增內容時，不需要重新向 AI 解釋整個專案。

## 我如何設計 AGENTS.md

文件分成八個部分：專案目的與邊界、技術與檔案結構、視覺及手機介面、學習單元格式、內容及資料規則、AI 開發流程、GitHub 與發布方式，以及可直接重複使用的任務提示。

規則具體到可以檢查，例如：文章檔名必須與 slug 一致、至少有三個章節、必須有練習步驟、牌卡 ID 必須存在；抽牌按鈕要在中央，卡池只能是全部、大牌、小牌，手機抽牌主畫面不得需要捲動。

## 我如何依照規則製作網頁

先建立 `AGENTS.md`，再依規則建立 `templates/lesson.json` 與共用產生器。網站內的「先看圖，再讀牌」及「用一張牌寫學習筆記」，都使用同樣的 JSON 格式產生。

每次執行 `npm run build`，程式會先驗證內容，再產生文章網頁、作業入口與規則網頁。這使內容和畫面分開，修改版型時不需要逐篇改 HTML。

## 與只做一個網頁的差別

以前的工作重點是把當前畫面做好；這次把「下一個畫面應該如何做」也定義下來。

例如要新增「觀察魔術師」，只需要複製 JSON 範本、填入內容與 `major_01`，然後重新建置。AI 不必自由猜測版型、檔案位置或格式，網站入口也會自動加入新文章。

## 建議展示順序

1. 開啟 GitHub 根目錄的 `AGENTS.md`，說明規則如何約束 AI。
2. 展示 `templates/lesson.json` 與其中一篇真實內容檔案。
3. 開啟公開作業網站的 `assignment.html`，進入文章。
4. 開啟 App 的抽牌練習，展示手機一屏、卡池切換與置中按鈕。
5. 說明可透過新增 JSON 繼續擴充，而不是每次重新製作頁面。
